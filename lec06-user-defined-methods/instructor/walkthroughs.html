Problem 1 · About 7 minutes

Print a heading twice

PrintHeading.java

Supporting slides 3–8IDE checkpoint: slide 8.

Problem description

A course practice program needs to display the same heading at two points. Write a Java program named PrintHeading.java that defines the heading once and reuses it.

  1. Define public static void printHeading(). It must print ICS 108 on one line and Methods practice on the next line. It takes no arguments and returns no value.
  2. In main, call printHeading(), print Start on its own line, then call printHeading() again.
  3. Keep the two heading-print statements inside printHeading only; do not repeat them in main. No keyboard input is required.
ConsoleExpected output
ICS 108
Methods practice
Start
ICS 108
Methods practice

What new concepts does it have?

Students will learnDefine and call a void method, then trace how execution returns to main.

  • P1-C1Defining methods
  • P1-C2Void is used for actions
  • P1-C3Calling methods
  • P1-C4Methods return to the caller

Complete code

Pause at each teaching comment. Explain its matching slide, then continue. Run: javac PrintHeading.java; java PrintHeading.

PrintHeading.javaComplete
public class PrintHeading {
   // P1-C1: Methods belong inside the class, outside main.
   // P1-C2: void means no value is returned.
   public static void printHeading() {
      System.out.println("ICS 108");
      System.out.println("Methods practice");
   }

   public static void main(String[] args) {
      // P1-C3: A name and parentheses form a method call.
      printHeading();
      System.out.println("Start");
      // P1-C4: Each call runs the body and returns to the caller.
      printHeading();
   }
}

Elaborated concepts for instructor reference

P1-C1 Defining methods

A method is a named group of statements. A definition supplies the name and body. Defining a method does not run it.

Rule: Each method is defined inside the class, at the same level as main.

P1-C2 Void is used for actions

A void method returns no value. It can still perform an action such as writing text to the console.

Rule: Printing text is different from returning a value.

P1-C3 Calling methods

A method call runs the method body. Use the method name followed by parentheses. No input means empty parentheses.

Rule: The call printHeading(); executes the helper.

P1-C4 Methods return to the caller

After a method finishes, execution continues after the call. Calling it again runs the same definition again.

Rule: One definition can be called more than once.

Traces, predictions, and checks

Trace: main → helper (two lines) → main prints Start → helper (two lines) → main ends. Check: move the definition below main: same output. Delete the second call: only the first three lines remain. Teaching note: public allows access from other classes; static lets main call without constructing an object.

Recovery: Nested helper definition or missing (): restore a class-level definition and printHeading();. int x = printHeading(); fails because void returns no value. Rebuild and rerun the same data after each fix.

Problem 2 · About 9 minutes

Convert hours and minutes

MinutesConverter.java

Supporting slides 9–13IDE checkpoint: slide 13.

Problem description

A study planner records each study session as hours and extra minutes. It needs the total duration in minutes. Write a Java program named MinutesConverter.java. Remember that one hour equals 60 minutes.

  1. Define public static int toMinutes(int hours, int minutes). It must return the total number of minutes without printing anything.
  2. In main, call the method for 1 hour and 30 minutes. Store the result in first and print it with the label First: followed by a space.
  3. Call it again using 1 + 1 as the hours argument and 5 as the minutes argument. Store the result in second and print it with the label Second: followed by a space.
  4. No keyboard input is required. Assume nonnegative whole hours, extra minutes from 0 to 59, and totals that fit int.
ConsoleExpected output
First: 90
Second: 125

What new concepts does it have?

Students will learnArguments match parameters by position, return one int, and store the result.

  • P2-C1Arguments match parameters
  • P2-C2Methods return one value
  • P2-C3Returned values can be stored
  • P2-C4Argument expressions are evaluated first

Complete code

Pause at each teaching comment. Explain its matching slide, then continue. Run: javac MinutesConverter.java; java MinutesConverter.

MinutesConverter.javaComplete
public class MinutesConverter {
   // P2-C1: Arguments fill typed parameters in the same order.
   public static int toMinutes(int hours, int minutes) {
      // P2-C2: The method returns one int value to the caller.
      return hours * 60 + minutes;
   }

   public static void main(String[] args) {
      // P2-C3: The returned value is stored before printing.
      int first = toMinutes(1, 30);
      System.out.println("First: " + first);
      // P2-C4: Argument expressions are evaluated before the call.
      int second = toMinutes(1 + 1, 5);
      System.out.println("Second: " + second);
   }
}

Elaborated concepts for instructor reference

P2-C1 Arguments match parameters

A parameter is a named input in the definition. An argument is a value supplied in a call. Each argument is assigned to its matching parameter by position.

Rule: First argument → hours. Second argument → minutes.

P2-C2 Methods return one value

An int method returns one int value. return evaluates its expression and immediately ends the current method call.

Rule: return hours * 60 + minutes; gives a value to the caller.

P2-C3 Returned values can be stored

A value-returning call is an expression. The caller can store its result in a variable and use that variable later.

Rule: int first = toMinutes(1, 30); stores 90 in first.

P2-C4 Argument expressions are evaluated first

An argument can be a literal, a variable, or an expression. Java evaluates the expression before assigning its value to the parameter.

Rule: toMinutes(1 + 1, 5) passes 2 and 5.

Traces, predictions, and checks

Trace: (1,30) → 1*60+30 → 90 → first; (1+1,5) → (2,5) → 125 → second. Checks: (0,0)→0; (0,59)→59; (2,0)→120; (3,15)→195. Prediction: swapping (1,30) to (30,1) compiles but returns 1801. The helper has no validation.

Recovery: Replacing return with println leaves an int method without a return. toMinutes(1) has too few arguments. Restore the full two-argument call and the return expression. Rebuild and rerun the same data after each fix.

Problem 3 · About 10 minutes

Update a score using a return value

ScoreUpdate.java

Supporting slides 14–20IDE checkpoint: slide 20.

Problem description

A practice app awards one extra point to a score. Write ScoreUpdate.java to compare calculating a new score with saving that score in the calling method.

  1. Define public static int addPoint(int score). Inside it, declare a local int named bonus with value 1, add bonus to the parameter score, and return score. Do not print inside this method.
  2. In main, create int score with value 7. Call addPoint(score), store the result in a separate variable named updated, and print score and updated with the labels Original: and Updated:.
  3. Call addPoint(score) again and print its returned value with the label Again:. Do not assign this result to score.
  4. Finally, call addPoint(score), assign its returned value back to score, and print score with the label Stored:. No keyboard input is required.
ConsoleExpected output
Original: 7
Updated: 8
Again: 8
Stored: 8

What new concepts does it have?

Students will learnExplain primitive parameter copies, local scope, fresh call state, and explicit assignment.

  • P3-C1Primitive arguments are copied
  • P3-C2Local variables have limited scope
  • P3-C3Each call has fresh local variables
  • P3-C4Assignment updates the caller’s variable

Complete code

Pause at each teaching comment. Explain its matching slide, then continue. Run: javac ScoreUpdate.java; java ScoreUpdate.

ScoreUpdate.javaComplete
public class ScoreUpdate {
   // P3-C1: score receives a copy of the caller's int value.
   public static int addPoint(int score) {
      // P3-C2: bonus is local to this method body.
      int bonus = 1;
      score = score + bonus;
      return score;
   }

   public static void main(String[] args) {
      int score = 7;
      int updated = addPoint(score);
      System.out.println("Original: " + score);
      System.out.println("Updated: " + updated);
      // P3-C3: A new call gets fresh parameters and locals.
      System.out.println("Again: " + addPoint(score));
      // P3-C4: Assignment updates the caller's score.
      score = addPoint(score);
      System.out.println("Stored: " + score);
   }
}

Elaborated concepts for instructor reference

P3-C1 Primitive arguments are copied

An int argument is passed by value: the parameter receives a copy. Assigning to that parameter changes only the copy.

Rule: Changing the helper’s score does not change main’s score.

P3-C2 Local variables have limited scope

A local variable is declared inside a method body or a smaller block. Its name is usable from its declaration to the end of that enclosing block.

Rule: bonus belongs to addPoint; main cannot use that name.

P3-C3 Each call has fresh local variables

Each call creates its own parameters and local variables. After return, those variables are no longer available to the caller.

Rule: Two calls with argument 7 both return 8.

P3-C4 Assignment updates the caller’s variable

A method can return a changed value without changing the caller’s variable. An assignment in the caller performs that update explicitly.

Rule: score = addPoint(score); replaces main’s score with the result.

Traces, predictions, and checks

Trace: caller 7 → copied parameter 7 → helper 8 → updated 8, caller still 7. Another call returns 8 again. Assignment back changes caller to 8. Checks: addPoint(0)→1; addPoint(-1)→0. Transfer: a second assignment-back would store 9; a second discarded call would not.

Recovery: Using bonus in main is a scope error. Ignoring the returned int leaves main score unchanged. Restore the proper local use and assignment-back line. Rebuild and rerun the same data after each fix.

User-defined methods: inputs, local work, and results.

Lecture abstract

A method groups statements under one name. Calling it runs those statements with the supplied inputs. A void method returns control without a value; an int method returns one integer. Parameters and local variables belong to each call, so changing an int parameter does not change the caller’s variable. This lecture develops these rules through a heading printer, a minutes converter, and a score update. It selects the foundation of Chapter 6; array references, overloading, and larger programs remain for later study.

Problem 1 · P1-C1zyBooks §6.1 · pp. 4–5

Define a method

A method is a named group of statements. A definition supplies the name and body. Defining a method does not run it.

Key rule

Put each method inside the class, at the same level as main.

Expand explanation, trace, and common error

How it works and when it matters

In PrintHeading.java, the helper and main have separate brace pairs. The outer braces enclose the class. public allows access from other classes; static makes this a class method callable from static main without creating an object. These modifiers are a teaching convention here, not the definition of all possible Java methods.

Misconception and recovery

Do not put the helper definition inside main. Move it outside main, keep it inside the class, rebuild, and run.

Useful teaching sentence

Put each method inside the class, at the same level as main.

Problem 1 · P1-C2zyBooks §6.1–6.2 · pp. 6–9, 18–20

Use void for an action

A void method returns no value. It can still perform an action such as writing text to the console.

Key rule

Printing text is different from returning a value.

Expand explanation, trace, and common error

How it works and when it matters

printHeading contains two println statements. Reaching its closing brace returns control to the caller. It does not return the printed text or the number 0. A bare return; can end a void method early, but is unnecessary here.

Misconception and recovery

int result = printHeading(); cannot compile: the call produces no int. Call printHeading(); as a statement.

Useful teaching sentence

Printing text is different from returning a value.

Problem 1 · P1-C3zyBooks §6.1 · pp. 4–5, 11

Call the method

A method call runs the method body. Use the method name followed by parentheses. No input means empty parentheses.

Key rule

Use printHeading(); to execute the helper.

Expand explanation, trace, and common error

How it works and when it matters

The program starts in main, even though the helper definition appears first. At printHeading(), main pauses while both output statements run. The semicolon completes the call statement. Moving the helper below main does not change its availability in this class.

Misconception and recovery

Writing printHeading without () is not a call. A missing call means the helper body never runs.

Useful teaching sentence

Use printHeading(); to execute the helper.

Problem 1 · P1-C4zyBooks §6.2–6.3, 6.7 · pp. 20, 26–29, 58

Return to the caller and reuse

After a method finishes, execution continues after the call. Calling it again runs the same definition again.

Key rule

One definition can be called more than once.

Expand explanation, trace, and common error

How it works and when it matters

Trace: first call prints the two heading lines; main prints Start; second call prints the two heading lines again; main ends. Changing one heading statement changes both calls. Develop incrementally: run one call, then add Start and the second call.

Misconception and recovery

A method does not run just once because it was defined once. Remove the second call to predict a three-line output, then restore and rerun.

Useful teaching sentence

One definition can be called more than once.

Problem 2 · P2-C1zyBooks §6.1, 6.4 · pp. 9–13, 39–40

Match arguments to parameters

A parameter is a named input in the definition. An argument is a value supplied in a call. Each argument is assigned to its matching parameter by position.

Key rule

First argument → hours. Second argument → minutes.

Expand explanation, trace, and common error

How it works and when it matters

For toMinutes(1, 30), hours receives 1 and minutes receives 30. The definition declares int for both parameters; the call supplies two int-compatible values. Names in the caller need not match parameter names. Here the intended inputs are whole nonnegative hours and minutes 0–59.

Misconception and recovery

toMinutes(30, 1) compiles but means 30 hours and 1 minute: 1801. toMinutes(1) fails to compile because a required argument is missing.

Useful teaching sentence

First argument → hours. Second argument → minutes.

Problem 2 · P2-C2zyBooks §6.1, 6.8 · pp. 6–9, 62–63

Return one result

An int method returns one int value. return evaluates its expression and immediately ends the current method call.

Key rule

return hours * 60 + minutes; gives a value to the caller.

Expand explanation, trace, and common error

How it works and when it matters

For (1, 30), the expression is 1 * 60 + 30, giving 90. The call then evaluates to 90. The return statement does not print it. Replacing return with println leaves an int method without its required result. Every normally completing path of an int method must return an int-compatible value.

Misconception and recovery

Do not return the wrong variable or a double from this int method. Restore the integer expression, rebuild, and rerun the same call.

Useful teaching sentence

return hours * 60 + minutes; gives a value to the caller.

Problem 2 · P2-C3zyBooks §6.1, 6.8 · pp. 6–9, 62

Store the returned value

A value-returning call is an expression. The caller can store its result in a variable and use that variable later.

Key rule

int first = toMinutes(1, 30); stores 90 in first.

Expand explanation, trace, and common error

How it works and when it matters

Read the right side first: the call runs and produces 90. Assignment initializes first with that value. Only the following println writes First: 90. Calling toMinutes(1, 30); alone is legal, but this program would discard its result.

Misconception and recovery

Do not expect a calculation-only helper to display anything. Keep output in main so the same helper can be reused without extra console text.

Useful teaching sentence

int first = toMinutes(1, 30); stores 90 in first.

Problem 2 · P2-C4zyBooks §6.1 · pp. 9–13

Evaluate argument expressions

An argument can be a literal, a variable, or an expression. Java evaluates the expression before assigning its value to the parameter.

Key rule

toMinutes(1 + 1, 5) passes 2 and 5.

Expand explanation, trace, and common error

How it works and when it matters

First evaluate 1 + 1 to 2. Copy 2 into hours and 5 into minutes. Compute 2 * 60 + 5 = 125. Return 125 and store it in second. The parameter never receives the written expression itself.

Misconception and recovery

The definition declares an input such as int hours; it does not declare int hours + 1. Put calculations in the call or method body.

Useful teaching sentence

toMinutes(1 + 1, 5) passes 2 and 5.

Problem 3 · P3-C1zyBooks §6.9 · p. 66

Copy a primitive value

An int argument is passed by value: the parameter receives a copy. Assigning to that parameter changes only the copy.

Key rule

Changing the helper’s score does not change main’s score.

Expand explanation, trace, and common error

How it works and when it matters

Both methods use the name score, but they declare separate variables. With main score = 7, addPoint receives 7, changes its own score to 8, and returns 8. main score remains 7. The returned value can be stored elsewhere. Java also copies reference values, but shared array mutation is a later topic.

Misconception and recovery

Do not claim that the matching variable name connects the two variables. Renaming the parameter leaves the behavior unchanged.

Useful teaching sentence

Changing the helper’s score does not change main’s score.

Problem 3 · P3-C2zyBooks §6.10 · pp. 72–73

Keep local variables in scope

A local variable is declared inside a method body or a smaller block. Its name is usable from its declaration to the end of that enclosing block.

Key rule

bonus belongs to addPoint; main cannot use that name.

Expand explanation, trace, and common error

How it works and when it matters

The helper declares int bonus = 1 and uses it to calculate score + bonus. main cannot access bonus, and addPoint cannot access main’s updated variable. A parameter is available inside its method body. Pass required data as arguments and return the needed result.

Misconception and recovery

Printing bonus in main fails to compile. Remove that out-of-scope reference; do not add a class field merely to avoid parameters.

Useful teaching sentence

bonus belongs to addPoint; main cannot use that name.

Problem 3 · P3-C3zyBooks §6.7 · pp. 58–59

Start each call with fresh state

Each call creates its own parameters and local variables. After return, those variables are no longer available to the caller.

Key rule

Two calls with argument 7 both return 8.

Expand explanation, trace, and common error

How it works and when it matters

The second addPoint(score) still receives main’s 7 because the first result was stored in updated. It creates a new parameter score = 7 and a new bonus = 1. It does not reuse the previous helper’s 8. A call’s local storage is often called a stack frame; bytecode details are outside this lecture.

Misconception and recovery

Two calls do not automatically accumulate to 9. To reach 9, store 8 into the caller’s score, then call and store again.

Useful teaching sentence

Two calls with argument 7 both return 8.

Problem 3 · P3-C4zyBooks §6.1, 6.9 · pp. 6–9, 66

Assign the result back

A method can return a changed value without changing the caller’s variable. An assignment in the caller performs that update explicitly.

Key rule

score = addPoint(score); replaces main’s score with the result.

Expand explanation, trace, and common error

How it works and when it matters

Evaluate the right side using the old score of 7. The method returns 8. Only then does assignment replace main’s score with 8. A second identical assignment would call with 8 and store 9. In the complete program the assignment occurs once, so Stored: 8 is correct.

Misconception and recovery

Do not ignore the return value when the goal is to update the caller. For addPoint, inputs must allow +1 to fit int; validation and overflow handling are deferred.

Useful teaching sentence

score = addPoint(score); replaces main’s score with the result.

Readiness self-check

  1. Does defining printHeading run it?
  2. Does a void method return 0?
  3. What does toMinutes(3, 15) return?
  4. What changes after int updated = addPoint(score), with score = 7?
  5. Why does a repeated call with 7 still return 8?
  6. Can main print the helper’s bonus variable?
  7. How can two calls change main score from 7 to 9?
Show answers after trying
  1. No. main must call it.
  2. No. void returns no value; it can still print.
  3. 195; the helper itself prints nothing.
  4. The helper parameter becomes 8; updated receives 8; main score stays 7.
  5. Each call gets fresh state copied from the unchanged caller.
  6. No. bonus is outside main’s scope.
  7. Execute score = addPoint(score); twice, storing 8 and then 9.

Problem 1 · About 8 minutes

Show a campus wallet balance

CampusWallet1.java

Supporting slides 3–8IDE checkpoint: slide 8.

Problem description

A student has 20 SAR in a campus wallet. Write a program that stores this balance and displays it as shown.

No keyboard input is required.

ConsoleExpected output
Balance: 20 SAR

What new concepts does it have?

Students will learnDistinguish a class, an object, and a reference; access an object’s field.

  • P1-C1Classes define types
  • P1-C2Instance fields store object data
  • P1-C3Objects are class instances
  • P1-C4Reference variables refer to objects
  • P1-C5The dot operator accesses members

Complete code

Instructor solution · Pause at each concept ID. Run: javac CampusWallet1.java, then java CampusWallet1.

CampusWallet1.javaComplete
// P1-C1: A class defines a type for campus wallet objects.
public class CampusWallet1 {
   // P1-C2: Each wallet has an instance field named balance.
   public int balance;

   public static void main(String[] args) {
      // P1-C3: new creates one object of this class.
      // P1-C4: wallet stores a reference to that object.
      CampusWallet1 wallet = new CampusWallet1();
      // P1-C5: The dot selects a member of this object.
      wallet.balance = 20;
      System.out.println("Balance: " + wallet.balance + " SAR");
   }
}

KeywordsTypesStringsNumbersComments

Elaborated concepts for instructor reference

P1-C1 Classes define types

A class defines a type by declaring its fields and methods. CampusWallet1 is the type; wallet is a variable. The class declaration alone creates no wallet object.

P1-C2 Instance fields store object data

An instance field is a variable declared in the class, outside methods, without static. balance belongs to a wallet and keeps its value between method calls. A local variable belongs to a method or block.

P1-C3 Objects are class instances

An object is one instance of a class. new CampusWallet1() creates one. With no declared constructor, Java supplies a no-argument constructor. The int field initially holds 0; the next assignment sets it to 20.

P1-C4 Reference variables refer to objects

wallet stores a reference to the object, not the balance itself. Declaring a reference alone does not create an object. The class name before wallet specifies which type of object it can refer to.

P1-C5 The dot operator accesses members

wallet.balance selects this wallet’s field. The same dot syntax later selects methods, such as wallet.getBalance(). A field access has no parentheses; a method call has parentheses.

Traces, predictions, and checks

Trace: create one object → set its balance to 20 → read 20 for printing. Change 20 to 0: the output becomes Balance: 0 SAR. Public field access is a first step; Problem 2 puts operations around the data.

Recovery: Removing new leaves no initialized object to use. Bare balance in static main needs an object reference. Restore the creation and wallet.balance, rebuild, and rerun.

Problem 2 · About 8 minutes

Add money to the same wallet

CampusWallet2.java

Supporting slides 9–12IDE checkpoint: slide 12.

Problem description

Extend Problem 1 so the student can add 10 SAR to the wallet’s 20 SAR balance. Display the balance before and after the addition.

No keyboard input is required.

ConsoleExpected output
Before: 20 SAR
After: 30 SAR

What new concepts does it have?

Students will learnExplain encapsulation and distinguish methods that change state from methods that read it.

  • P2-C1Encapsulation hides internal data
  • P2-C2Mutators change object state
  • P2-C3Accessors read object state

Complete code

Instructor solution · Pause at each concept ID. Run: javac CampusWallet2.java, then java CampusWallet2.

CampusWallet2.javaComplete
public class CampusWallet2 {
   // P2-C1: private keeps the field inside the class's implementation.
   private int balance = 20;

   // P2-C2: A mutator changes the receiving object's state.
   public void addMoney(int amount) {
      balance = balance + amount;
   }

   // P2-C3: An accessor returns data without changing it.
   public int getBalance() {
      return balance;
   }

   public static void main(String[] args) {
      CampusWallet2 wallet = new CampusWallet2();
      System.out.println("Before: " + wallet.getBalance() + " SAR");
      wallet.addMoney(10);
      System.out.println("After: " + wallet.getBalance() + " SAR");
   }
}

KeywordsTypesStringsNumbersComments

Elaborated concepts for instructor reference

P2-C1 Encapsulation hides internal data

Encapsulation groups data with its operations and controls access. private hides balance from other classes; public exposes addMoney and getBalance. Because main is inside this same class, privacy does not prevent main from accessing balance; it uses the public methods to demonstrate the interface.

P2-C2 Mutators change object state

A mutator is a method that changes the receiving object. wallet.addMoney(10) adds 10 to that wallet’s stored balance. This method returns no value. Unlike Lecture 6’s preview, it changes the object immediately.

P2-C3 Accessors read object state

An accessor reads an object without changing its state. getBalance returns an int; println displays that returned value. Calling getBalance twice leaves the balance unchanged. Neither instance method is static.

Traces, predictions, and checks

Retain the same balance from Problem 1. Before the addition it is 20; afterward it is 30. Adding 0 leaves 20 unchanged. Two additions of 10 give 40. Reading twice makes no change. Use nonnegative whole SAR values whose sum fits int.

Recovery: Printing inside getBalance without returning an int fails to compile. An addition only to the parameter leaves the field unchanged. Restore the return or field assignment, rebuild, and rerun.

Problem 3 · About 10 minutes

Keep two students’ balances separate

CampusWallet3.java

Supporting slides 13–16IDE checkpoint: slide 16.

Problem description

Extend Problem 2 for two students whose wallets start at 20 SAR and 50 SAR. Add 10 SAR to the first wallet, then display both balances. The second balance must stay unchanged.

No keyboard input is required.

ConsoleExpected output
First: 30 SAR
Second: 50 SAR

What new concepts does it have?

Students will learnInitialize objects with constructors, explain this, and trace independent instance fields.

  • P3-C1Constructors initialize new objects
  • P3-C2this refers to the current object
  • P3-C3Objects have separate instance fields

Complete code

Instructor solution · Pause at each concept ID. Run: javac CampusWallet3.java, then java CampusWallet3.

CampusWallet3.javaComplete
public class CampusWallet3 {
   private int balance;

   // P3-C1: A constructor initializes an object during creation.
   public CampusWallet3(int balance) {
      // P3-C2: this.balance is the field; balance is the parameter.
      this.balance = balance;
   }

   public void addMoney(int amount) {
      balance = balance + amount;
   }

   public int getBalance() {
      return balance;
   }

   public static void main(String[] args) {
      // P3-C3: Two new expressions create separate instance fields.
      CampusWallet3 first = new CampusWallet3(20);
      CampusWallet3 second = new CampusWallet3(50);
      first.addMoney(10);
      System.out.println("First: " + first.getBalance() + " SAR");
      System.out.println("Second: " + second.getBalance() + " SAR");
   }
}

KeywordsTypesStringsNumbersComments

Elaborated concepts for instructor reference

P3-C1 Constructors initialize new objects

A constructor runs during object creation. It has the class’s exact name and no return type, not even void. The argument supplies each starting balance. Once this constructor is declared, Java no longer supplies a no-argument one.

P3-C2 this refers to the current object

this refers to the object being initialized or receiving a method call. In this.balance = balance, the left side is that object’s field; the right side is the parameter. balance = balance only assigns the parameter to itself.

P3-C3 Objects have separate instance fields

Each new expression creates a different wallet with its own balance. first.addMoney(10) changes only first’s object: 20 → 30; second stays 50. Keep the field non-static. second = first would share an object instead of copying it.

Traces, predictions, and checks

The two methods from Problem 2 are unchanged. Start both wallets at 20 and add 10 to first: results are 30 and 20. Start first at 0 and add 0: it stays 0. Use nonnegative whole SAR values whose sum fits int.

Recovery: Adding void makes the constructor an ordinary method. Omitting this silently leaves the field at 0. Making balance static shares it. Restore the constructor, field assignment, or instance field, rebuild, and rerun.

Classes and objects

Chapter abstract

A class defines a type that groups related fields and methods. An object is one instance of that type; a reference variable lets a program use it. Instance fields hold the object’s state. Public methods can provide access to private fields, and constructors establish the starting state. This lecture selects those foundations from Chapter 7 through three versions of one campus wallet: display a balance, add money through methods, then create two wallets with different starting balances. Each problem extends the preceding one. Collections, wrapper classes, and larger class designs remain for later study.

Classes define types

A class is a definition of a type. It groups related fields and methods. A field is a variable declared in a class; a method supplies an operation. Defining a class makes that type available, but does not by itself create an object.

Key rule

The class defines the type; an object is an instance of that type.

Expand explanation, trace, and common error

How it works and when it matters

public class CampusWallet1 introduces the type CampusWallet1. Its braces contain the field and the familiar main method. In later extensions, this same kind of wallet also has methods for adding money and reading the balance. A class keeps the data and operations for one kind of thing together.

Each problem uses one public class and one file. The file name must match the public class name, including its capital letters. These three names identify successive versions of the same exercise; they do not imply inheritance.

Misconception and recovery

A class name is not the name of one particular wallet. CampusWallet1 is the type; wallet will be a variable referring to one object. If the file is named CampusWallet1.java but the public class still says CampusWallet2, restore the matching name and compile again.

Useful teaching sentence

The class says what a wallet can contain and do. We still need to create a wallet.

Instance fields store object data

An instance field is a variable that belongs to an object. It is declared inside the class, outside its methods, without static. Its value is part of the object’s state: the data the object holds at that moment.

Key rule

Put balance at class level so it belongs to each wallet object.

Expand explanation, trace, and common error

How it works and when it matters

public int balance;

This declaration is inside CampusWallet1 and outside main. The object holds an int balance. In Problem 1, public lets code in other classes access the field; Problem 2 will hide it. Public fields are used here only to make the first object easy to inspect.

Java initially gives an uninitialized int field the value 0. Problem 1 explicitly assigns 20 before printing. A local variable declared inside a method is different: it must be assigned before it is read. Problem 2 uses private int balance = 20;, so each newly created wallet starts at 20.

Misconception and recovery

Moving int balance; into main makes it a local variable, so it is no longer the object’s field. Move it back to class level. Do not add static to fix an access error: that changes the design to one shared class field. Static main can access an instance field through a reference such as wallet.balance.

Useful teaching sentence

Balance is data in the wallet object, so it stays with that object between method calls.

Problem 1 · P1-C3zyBooks §7.2, 7.5, 7.8 · pp. 8–10, 28–30, 43–45

Objects are class instances

An object is an instance of a class. A new expression creates an object and gives back a reference to it. Creating an object also runs a constructor, which initializes the new object.

Key rule

new CampusWallet1() creates one CampusWallet1 object.

Expand explanation, trace, and common error

How it works and when it matters

new CampusWallet1()

new creates the object. The class name gives its type, and the parentheses supply constructor arguments. The empty parentheses mean no arguments. Problem 1 declares no constructor, so Java supplies an implicit no-argument default constructor. Problem 3 will define a constructor explicitly.

A reference variable declaration by itself does not create a wallet. The complete program assigns the reference returned by new CampusWallet1() to wallet, and then gives the object’s balance the value 20.

Misconception and recovery

CampusWallet1 wallet; declares only a local reference variable. Trying to read or use it before assigning a value fails to compile. Restore the object creation. Do not replace new CampusWallet1() with CampusWallet1(): constructors are used as part of object creation, not as ordinary method calls.

Useful teaching sentence

Each time this new expression runs successfully, it creates a new wallet.

Problem 1 · P1-C4zyBooks §7.2, 7.8, 7.10 · pp. 8–10, 43–47, 54

Reference variables refer to objects

A reference variable stores a reference to an object, rather than the object’s fields. A variable with a class type, such as CampusWallet1, is a reference variable. An int variable stores an integer value directly.

Key rule

wallet refers to the object that contains balance.

Expand explanation, trace, and common error

Read the declaration in parts

CampusWallet1 wallet = new CampusWallet1();
  1. CampusWallet1 wallet declares the local reference variable and its type.
  2. new CampusWallet1() creates the object and produces a reference.
  3. = stores that reference in wallet.

Draw wallet → object { balance: 20 } after the assignment to the field. The arrow is a teaching representation of a reference; it is not a numeric memory address students can read in Java.

Misconception and recovery

One variable name does not guarantee one separate object. Assigning one reference variable to another copies the reference; it does not copy the object. The independence check in Problem 3 therefore uses two separate new expressions.

If a reference is explicitly set to null, it refers to no object. Using an instance field or calling an instance method through it causes a NullPointerException. Restore a valid object reference and rerun. This differs from reading a never-assigned local variable, which fails at compile time.

Useful teaching sentence

The variable lets us reach the object. The balance lives in the object.

Problem 1 · P1-C5zyBooks §7.2–7.3 · pp. 8–15

The dot operator accesses members

The dot operator selects a member of the object referred to by the expression before it. Members include fields and methods. Field access uses the field name; a method call also uses parentheses for its arguments.

Key rule

wallet.balance selects the balance field of the object wallet refers to.

Expand explanation, trace, and common error

How it works and when it matters

wallet.balance = 20;
System.out.println("Balance: " + wallet.balance + " SAR");

The first statement writes 20 into the field. The second reads that same field when constructing the output text. The complete Problem 1 output is:

Balance: 20 SAR

In Problem 2, wallet.addMoney(10) selects and calls a method on that wallet. The expression before the dot tells Java which object to use. Access rules still apply: a dot does not bypass private.

Misconception and recovery

wallet.balance() incorrectly treats the field as a method. Remove the parentheses. Writing only balance = 20; inside static main does not select a wallet instance; restore wallet.. These are compile-time errors, not arithmetic mistakes.

Useful teaching sentence

Before the dot is the object reference. After the dot is the member we want.

Problem 2 · P2-C1zyBooks §7.1, 7.3–7.5 · pp. 4–6, 12–15, 21–28

Encapsulation hides internal data

Encapsulation groups related data and operations and controls access to the data. A private field cannot be accessed directly from an unrelated class. Public methods provide the operations that other classes can use.

Key rule

Keep balance private and expose the wallet’s intended operations.

Expand explanation, trace, and common error

Extend the first wallet

private int balance = 20;

Problem 2 keeps the balance concept but hides direct field access from other classes. Its public operations are addMoney(int amount) and getBalance(). The initializer gives every new wallet 20 SAR before it is used. Calls do not need to know the field’s declaration to add money or read a balance.

Be precise about private

main is inside CampusWallet2 in this one-file exercise. It is therefore allowed to access this class’s private field through an object reference. Do not claim that wallet.balance fails there. A direct access from a separate, unrelated class fails. We deliberately use public methods in main to model how a caller should use the wallet.

Private is an access rule, not automatic input validation. addMoney could later check an amount in one place, but this lesson assumes nonnegative whole-SAR amounts and totals that fit int.

Misconception and recovery

Do not make the field public merely to make another class’s direct access compile. Use the intended accessor or mutator. If an access error is demonstrated in a separate scratch caller, restore the method call, rebuild, and rerun the same values.

Useful teaching sentence

The caller asks the wallet to do something; the wallet controls how its data is used.

Problem 2 · P2-C2zyBooks §7.3–7.4 · pp. 14–23

Mutators change object state

A mutator is a method that can change an object’s fields. Its purpose is defined by what it does to the object’s state. A setter is one kind of mutator; a mutator can also add to an existing value.

Key rule

addMoney changes the balance in the object on which it is called.

Expand explanation, trace, and common error

Trace the state change

public void addMoney(int amount) {
    balance = balance + amount;
}
  1. The wallet’s field holds 20.
  2. wallet.addMoney(10) supplies 10 to the local parameter amount.
  3. The assignment calculates 20 + 10 and stores 30 in the wallet’s field.
  4. The call returns to main. The field still holds 30.

The method is an instance method: there is no static keyword, and it acts on the selected wallet. Its void return type says it returns no value. Changing a field is still an effect of the call. This differs from the previous lecture’s primitive-copy preview: the assignment here targets an object’s field.

Misconception and recovery

Writing balance = amount; replaces 20 with 10 instead of adding to it. Restore balance = balance + amount; and rerun. A second call with 10 gives 40; a call with 0 leaves the balance unchanged. Negative amounts are not rejected by this implementation; domain checks are deferred.

Useful teaching sentence

The parameter is temporary input. The updated field stays in the wallet after the call ends.

Problem 2 · P2-C3zyBooks §7.4 · pp. 21–23

Accessors read object state

An accessor is a method that reads information without changing the object’s state. A getter is an accessor that returns a value. Accessor and mutator describe behavior; Java does not enforce those labels from a method’s name.

Key rule

getBalance returns the current balance without changing it.

Expand explanation, trace, and common error

How it works and when it matters

public int getBalance() {
    return balance;
}

The int return type means the caller receives one integer. return balance; reads the field; it does not print. The returned integer is a value, so storing it in a local variable does not give that variable control over the field.

Problem 2 reads the balance, adds 10, then reads it again. The two calls to the same accessor return different values because the mutator changed the object between them:

Before: 20 SAR
After: 30 SAR

Misconception and recovery

Repeated getBalance() calls alone do not add money. A name beginning with get does not prevent a programmer from writing an assignment in its body, but doing so would violate this accessor’s intended behavior. If the getter unexpectedly changes the value, remove that mutation and rerun. Changing return balance; to a print statement also leaves this int method without its required returned value.

Useful teaching sentence

The accessor reports the wallet’s state. The println in main decides how to display it.

Problem 3 · P3-C1zyBooks §7.5, 7.7 · pp. 27–30, 36–40

Constructors initialize new objects

A constructor initializes a new object. It has the same name as its class and has no return type, not even void. Arguments in a new expression supply values to the constructor’s parameters.

Key rule

new CampusWallet3(20) creates a wallet and supplies its starting balance.

Expand explanation, trace, and common error

Extend the second wallet

public CampusWallet3(int balance) {
    this.balance = balance;
}

Problem 2 gave every wallet the same starting value in its field declaration. Problem 3 keeps the private field and the same two public methods, but lets each creation supply a starting balance. The first creation supplies 20 and the second supplies 50. The assignment’s this is explained in the next concept.

Problem 1 and Problem 2 have no programmer-declared constructors, so Java supplies a default no-argument constructor. Once Problem 3 declares this constructor, Java does not also supply a no-argument one. This exercise intentionally requires the starting balance, so new CampusWallet3() is no longer supported. A programmer-written no-argument constructor and a compiler-supplied default constructor should not be confused.

Misconception and recovery

public void CampusWallet3(int balance) defines an ordinary method, not a constructor. Remove void. If a copied creation still has empty parentheses, supply the starting balance. Rebuild and rerun both wallets. Constructor overloading is deferred; one parameterized constructor is sufficient here.

Useful teaching sentence

The constructor sets the starting state while the object is being created.

Problem 3 · P3-C2zyBooks §7.9, 7.16 · pp. 47–53, 110–112

this refers to the current object

this is a reference to the current object inside an instance method or constructor. It can identify an object’s field when a parameter uses the same name. Static methods do not have a current object through this.

Key rule

In this.balance = balance, the left side is the field and the right side is the parameter.

Expand explanation, trace, and common error

Trace the constructor assignment

this.balance = balance;

In new CampusWallet3(20), the constructor parameter balance receives 20, and this refers to the new first wallet. The assignment stores 20 in that object’s field. During new CampusWallet3(50), this refers to the new second wallet, so 50 goes into its field instead.

In addMoney(int amount), the names balance and amount are different. Therefore balance already identifies the field, and this.balance is optional there. Using the same field and parameter name in the constructor makes the distinction visible.

Misconception and recovery

balance = balance; assigns the parameter to itself. It compiles but leaves the field at its default 0 in Problem 3. With the rest of the example unchanged, the output becomes First: 10 SAR and Second: 0 SAR. Restore this. on the left and rerun. this.balance in static main is a compile-time error; use an object reference there.

Useful teaching sentence

This balance belongs to the object. The unqualified balance is the constructor’s input.

Problem 3 · P3-C3zyBooks §7.2, 7.8, 7.16 · pp. 8–10, 43–47, 107

Objects have separate instance fields

Each separate object has its own instance fields. Two objects created from the same class can therefore hold different balances. Changing a field in one does not change the corresponding field in a different object.

Key rule

Two new expressions create two wallets with separate balances.

Expand explanation, trace, and common error

Trace both objects

CampusWallet3 first = new CampusWallet3(20);
CampusWallet3 second = new CampusWallet3(50);
first.addMoney(10);
MomentFirst walletSecond wallet
After both creations2050
After first.addMoney(10)3050

The public methods have the same definitions for both objects. The reference before each call selects whose fields the method reads or changes. The complete output is:

First: 30 SAR
Second: 50 SAR

Separate objects versus two references

If the second declaration were CampusWallet3 second = first;, there would be one wallet and two references to it. This is called aliasing. Calling first.addMoney(10) would then make both accessors report 30. Assignment copies the reference; only the second new creates the separate second wallet in the actual solution.

Misconception and recovery

Do not make balance static: a static field belongs to the class and is shared, so it cannot represent separate wallet balances. Keep the instance field and both creations. As an independent check, add 10 to the second wallet afterward: the results should be 30 and 60.

Useful teaching sentence

Same class means the same kind of object. Separate new expressions give us separate object state.

Before teaching

Readiness self-check

  1. Does declaring CampusWallet1 wallet; create a wallet?
  2. Where is the balance stored: in the reference variable or in the object?
  3. Why can main access a private field in this one-class exercise?
  4. What is the difference between addMoney(10) and getBalance()?
  5. Why does Problem 3 require an argument in new CampusWallet3(20)?
  6. What goes wrong if the constructor says balance = balance;?
  7. Why does the second wallet stay at 50 after adding 10 to the first?
  8. What changes if the second declaration is CampusWallet3 second = first;?
Show answers after trying
  1. No. It declares a reference variable. A new expression creates the object.
  2. The int balance is an instance field in the object. The variable stores a reference to that object.
  3. Because main is defined in the same class. Private restricts access from unrelated classes; it does not block methods inside its own class.
  4. addMoney changes the selected wallet’s state and returns no value. getBalance returns the current integer balance without changing state.
  5. The class declares one constructor that requires an int. Java supplies no implicit default constructor once a constructor is declared.
  6. It assigns the parameter to itself and leaves the field at 0. Use this.balance = balance;.
  7. Two separate new expressions created two objects. Each has its own balance field.
  8. Both variables refer to one object. After adding 10 to its starting 20, both accessors report 30.

Problem 1 · About 9 minutes

Two ways to start a wallet

CampusWallet8A.java

Supporting slides 3–6IDE checkpoint: slide 6.

Problem description

A standard campus wallet starts with 20 SAR; a custom wallet starts with 50 SAR. Display both starting balances.

No keyboard input is required.

ConsoleExpected output
Standard: 20 SAR
Custom: 50 SAR

What new concepts does it have?

Students will learnUse two constructors for different starting balances and share initialization.

  • P1-C1Constructor overloading
  • P1-C2Constructor chaining
  • P1-C3Constructor selection

Complete code

Instructor solution · Pause at each concept ID. Run: javac CampusWallet8A.java, then java CampusWallet8A.

CampusWallet8A.javaComplete
public class CampusWallet8A {
   private int balance;

   // P1-C1: Constructors can share a name when their parameters differ.
   public CampusWallet8A() {
      // P1-C2: This constructor delegates to the int constructor.
      this(20);
   }

   public CampusWallet8A(int balance) {
      this.balance = balance;
   }

   public void addMoney(int amount) {
      balance += amount;
   }

   public int getBalance() {
      return balance;
   }

   public static void main(String[] args) {
      // P1-C3: Arguments select the matching constructor.
      CampusWallet8A standard = new CampusWallet8A();
      CampusWallet8A custom = new CampusWallet8A(50);
      System.out.println("Standard: " + standard.getBalance() + " SAR");
      System.out.println("Custom: " + custom.getBalance() + " SAR");
   }
}

Elaborated concepts for instructor reference

P1-C1 Constructor overloading

The two constructors have the same class name, no return type, and different parameters. A return type alone cannot distinguish overloads. Keep both forms so the previous wallet operations still work. Check: If the no-argument constructor is removed, new CampusWallet8A() fails to compile. Restore it and rebuild.

P1-C2 Constructor chaining

The no-argument constructor delegates to the int constructor. The latter performs the field assignment once. this(20) invokes a constructor; this.balance selects a field. Check: Putting any statement before this(20) fails to compile. Move the delegation to the first statement.

P1-C3 Constructor selection

No arguments select the standard wallet constructor. One int selects the custom-balance constructor. Java chooses by parameter types and count, not the assignment variable name. Check: Changing 50 to a String has no matching constructor. Supply an int or define an appropriate overload.

Problem 2 · About 12 minutes

Transfer through another name

CampusWallet8B.java

Supporting slides 7–10IDE checkpoint: slide 10.

Problem description

Extend Problem 1: transfer 10 SAR from the custom wallet to the standard wallet. Another name for the custom wallet should report its updated balance, while the transfer amount remains 10.

No keyboard input is required.

ConsoleExpected output
Standard: 30 SAR
Custom: 40 SAR
Alias: 40 SAR
Amount: 10

What new concepts does it have?

Students will learnDistinguish aliases, primitive values, and object-reference parameters.

  • P2-C1Aliasing
  • P2-C2Primitive values
  • P2-C3Reference parameters

Complete code

Instructor solution · Pause at each concept ID. Run: javac CampusWallet8B.java, then java CampusWallet8B.

CampusWallet8B.javaComplete
public class CampusWallet8B {
   private int balance;

   public CampusWallet8B() {
      this(20);
   }

   public CampusWallet8B(int balance) {
      this.balance = balance;
   }

   public void addMoney(int amount) {
      balance += amount;
   }

   public int getBalance() {
      return balance;
   }

   public static void main(String[] args) {
      CampusWallet8B standard = new CampusWallet8B();
      CampusWallet8B custom = new CampusWallet8B(50);
      // P2-C1: Assigning a reference makes another name for the same object.
      CampusWallet8B alias = custom;
      // P2-C2: The int variable contains its number directly.
      int amount = 10;
      alias.transferTo(standard, amount);
      System.out.println("Standard: " + standard.getBalance() + " SAR");
      System.out.println("Custom: " + custom.getBalance() + " SAR");
      System.out.println("Alias: " + alias.getBalance() + " SAR");
      System.out.println("Amount: " + amount);
   }

   // P2-C3: The recipient parameter receives a copy of an object reference.
   public void transferTo(CampusWallet8B recipient, int amount) {
      balance -= amount;
      recipient.addMoney(amount);
      amount = 0; // Only this local primitive copy changes.
   }
}

Elaborated concepts for instructor reference

P2-C1 Aliasing

alias and custom refer to one wallet, so either name sees its changed balance. Assigning the reference does not make a second wallet. A second new expression would. Check: If alias is created with new, the two balances can diverge. Assign the existing reference to demonstrate sharing.

P2-C2 Primitive values

The caller amount remains 10. Inside transferTo, the int parameter gets its own copy; setting it to 0 does not change the caller variable. The copied value can still be used to change object fields. Check: Do not claim the transfer changed the caller amount. Print it after the call to check.

P2-C3 Reference parameters

The recipient parameter is a local reference to the standard wallet. Calling recipient.addMoney changes that object. Java passes values: the value of a reference variable is copied, rather than an object being passed by reference. Reassigning recipient would not rebind the caller variable. Check: If transferTo creates a new recipient instead of using the argument, the standard wallet remains at 20. Use the passed reference.

Problem 3 · About 13 minutes

Add an optional reward

CampusWallet8C.java

Supporting slides 11–15IDE checkpoint: slide 15.

Problem description

Extend Problem 2: the standard wallet may have a 5 SAR reward. Show its available balance with the reward and after the reward is cleared; retain the transfer results.

No keyboard input is required.

ConsoleExpected output
Standard: 30 SAR
Custom: 40 SAR
Alias: 40 SAR
Amount: 10
With reward: 35 SAR
Without reward: 30 SAR

What new concepts does it have?

Students will learnUse an optional Integer safely and recognize automatic boxing and unboxing.

  • P3-C1Wrapper class
  • P3-C2null reference
  • P3-C3Unboxing
  • P3-C4Autoboxing

Complete code

Instructor solution · Pause at each concept ID. Run: javac CampusWallet8C.java, then java CampusWallet8C.

CampusWallet8C.javaComplete
public class CampusWallet8C {
   private int balance;
   // P3-C1: Integer is a reference type that represents an int value.
   private Integer reward;

   public CampusWallet8C() { this(20); }
   public CampusWallet8C(int balance) { this.balance = balance; }
   public void addMoney(int amount) { balance += amount; }
   public int getBalance() { return balance; }

   public void transferTo(CampusWallet8C recipient, int amount) {
      balance -= amount;
      recipient.addMoney(amount);
      amount = 0;
   }

   public void setReward(Integer reward) { this.reward = reward; }

   public int getAvailableBalance() {
      // P3-C2: null represents an absent optional reward.
      if (reward == null) { return balance; }
      // P3-C3: Arithmetic unboxes Integer to int.
      return balance + reward;
   }

   public static void main(String[] args) {
      CampusWallet8C standard = new CampusWallet8C();
      CampusWallet8C custom = new CampusWallet8C(50);
      CampusWallet8C alias = custom;
      int amount = 10;
      alias.transferTo(standard, amount);
      System.out.println("Standard: " + standard.getBalance() + " SAR");
      System.out.println("Custom: " + custom.getBalance() + " SAR");
      System.out.println("Alias: " + alias.getBalance() + " SAR");
      System.out.println("Amount: " + amount);
      // P3-C4: Passing int 5 to an Integer parameter autoboxes it.
      standard.setReward(5);
      System.out.println("With reward: " + standard.getAvailableBalance() + " SAR");
      standard.setReward(null);
      System.out.println("Without reward: " + standard.getAvailableBalance() + " SAR");
   }
}

Elaborated concepts for instructor reference

P3-C1 Wrapper class

int holds a primitive value directly. Integer refers to an immutable wrapper object representing an int. A wrapper can be used where an object is required, such as a generic collection or an optional field. The reference can also be null. Check: Do not use new Integer(...); constructors are deprecated in modern Java. Autoboxing or Integer.valueOf is preferable.

P3-C2 null reference

No reward differs from a reward of zero. The nullable Integer field starts as null, and clearing it returns to that state. Check null before arithmetic, because arithmetic would unbox the value. Check: If reward is null and is unboxed, a NullPointerException occurs. Guard the use and return the base balance.

P3-C3 Unboxing

The + operator needs numeric values; Java unboxes reward to int after the null check. The expression computes a new int and leaves the Integer object unchanged. Wrapper objects are immutable. Check: Moving balance + reward before the null check can crash when there is no reward.

P3-C4 Autoboxing

The literal 5 is an int and setReward expects Integer, so Java boxes it automatically. The parameter receives a reference value. Clearing with null selects absence without pretending that the reward is zero. Check: An Integer object should be compared by value with equals, not assumed equal by == identity. This example only compares to null.

ICS 108 · Lecture 17 · Instructor concept refresher

JavaFX events, validation, and images

Extend Monday’s static booking form so the user can enter a seat count, calculate a total, recover from invalid input, and browse venue images. The interface is built once; handlers run later in response to actions. Input remains text until it is parsed and checked. Images are data displayed by an ImageView, and a field remembers the selected picture between clicks.

Mental model: Build once → wait for an event → read current state → validate or change state → update the visible controls → wait again.

P1-C2 · 10.5 · pp. 15–18

Button action handler

An action handler is code JavaFX calls when a control fires an action event. The anonymous class creates an EventHandler object without declaring a separate class name. EventHandler<ActionEvent> means this handler accepts action events; handle is the required method. The outer }); closes the anonymous class, the method call, and its statement. Our examples use fields for shared controls and the updateTotal helper to keep the event template short.

Key rule: setOnAction registers the handler; handle runs later for each action.

Worked example and common mistakes
calc.setOnAction(new EventHandler<ActionEvent>() {
  @Override public void handle(ActionEvent event) {
    updateTotal();
  }
});

The anonymous class creates an EventHandler object without declaring a separate class name. EventHandler<ActionEvent> means this handler accepts action events; handle is the required method. The outer }); closes the anonymous class, the method call, and its statement. Our examples use fields for shared controls and the updateTotal helper to keep the event template short.

Common mistakes: Do not confuse handler registration with handler execution.

Another context and its result
save.setOnAction(new EventHandler<ActionEvent>() {
  @Override public void handle(ActionEvent event) {
    status.setText("Saved");
  }
});

Outcome: Assuming the named controls/helpers exist, registering does not update the total or status. Firing the corresponding button does.

What stays the same: setOnAction registers the handler; handle runs later for each action.

Predict: Would calling updateTotal() before setOnAction make it run on every later click?

Prediction answer

No. That call runs immediately. Put the call inside handle to respond to each action.

Parsing an integer

Integer.parseInt converts integer text into an int or throws NumberFormatException. Problem 1 deliberately assumes integer inputs from 1 to 4; Problem 2 adds recovery. Empty text, nonnumeric text, and values outside the int range fail parsing. A parseable value such as 0 still needs a booking rule. trim removes surrounding whitespace when we introduce validation.

Key rule: getText reads a String; parseInt performs the numeric conversion.

Worked example and common mistakes
int seats = Integer.parseInt(input.getText());
output.setText(Integer.toString(seats * 10));

P2-C1 · 10.5 · pp. 18–20; explicit parse recovery is a teaching addition

Validation order

Input validation checks both its text format and the permitted value range. Trim first, parse inside try, test the range, then calculate. Clearing the old total before validation prevents an old successful total from looking like the result of the invalid input. Return exits only this helper call; the application remains open for correction.

Key rule: Parse first, then check the booking range before updating the total.

Worked example and common mistakes
int seats = Integer.parseInt(input.getText().trim());
if (seats < 1 || seats > 4) {
  showError("Choose 1 to 4 seats.");
  return;
}

Trim first, parse inside try, test the range, then calculate. Clearing the old total before validation prevents an old successful total from looking like the result of the invalid input. Return exits only this helper call; the application remains open for correction.

Common mistakes: Do not use an old total as the apparent result for invalid new input.

Another context and its result
int mark = Integer.parseInt("105");
if (mark < 0 || mark > 100) {
  System.out.println("Invalid mark");
}

Outcome: The first code requires the helper shown in Problem 2. The marks example prints Invalid mark even though parsing succeeded.

What stays the same: Parse first, then check the booking range before updating the total.

Predict: Does parsing "0" throw NumberFormatException?

Prediction answer

No. It produces 0. Our range check rejects that value afterward.

Error alerts

An Alert is a dialog that reports information or asks for a response. The showError helper sets the title and removes the default header so the student sees one clear message. ERROR, INFORMATION, WARNING, CONFIRMATION, and NONE communicate different purposes. A confirmation decision requires inspecting the returned button choice; that is outside these problems. showAndWait pauses this call until dismissal while JavaFX continues processing UI events.

Key rule: Use AlertType.ERROR for invalid input and showAndWait to display it.

Worked example and common mistakes
Alert alert = new Alert(AlertType.ERROR, message);
alert.showAndWait();

The showError helper sets the title and removes the default header so the student sees one clear message. ERROR, INFORMATION, WARNING, CONFIRMATION, and NONE communicate different purposes. A confirmation decision requires inspecting the returned button choice; that is outside these problems. showAndWait pauses this call until dismissal while JavaFX continues processing UI events.

Common mistakes: An alert is feedback; it does not itself prevent invalid calculations.

Another context and its result
Alert alert = new Alert(AlertType.INFORMATION, "Saved");

Prediction answer

No. Call show or showAndWait. Our program uses showAndWait inside the event handler.

P2-C3 · 10.5 validation context + Chapter 9 exception recap

Recovery inside an event

Catching an input exception inside a handler allows a later corrected action. The exception is caused by the current text, not by the button itself. Keep the protected operation inside try. The catch shows a specific message and leaves the result blank. Replacing the input and clicking again is the GUI equivalent of retrying the console input loop.

Key rule: Catch NumberFormatException and finish this action without closing the window.

Worked example and common mistakes
try {
  int seats = Integer.parseInt(text);
} catch (NumberFormatException e) {
  showError("Enter a whole number.");
}

The exception is caused by the current text, not by the button itself. Keep the protected operation inside try. The catch shows a specific message and leaves the result blank. Replacing the input and clicking again is the GUI equivalent of retrying the console input loop.

Common mistakes: Do not catch every Exception when only integer-format failure is expected.

Another context and its result
try {
  int mark = Integer.parseInt("absent");
} catch (NumberFormatException e) {
  System.out.println("No numeric mark");
}

Outcome: The booking fragment uses the text and helper from the worked program. The marks fragment prints No numeric mark.

What stays the same: Catch NumberFormatException and finish this action without closing the window.

Predict: After an error dialog is dismissed, must the application restart to accept 2?

Prediction answer

No. The next click calls the handler again, reads the corrected text, and displays 20.

Image display size

ImageView can fit an image to a target width while preserving its aspect ratio. The view fits within the booking form without stretching the diagram. We set only fitWidth; JavaFX derives height from the original ratio. Display scaling does not resize or overwrite the PNG file.

Key rule: Set fitWidth and preserveRatio on the view, not on the source image.

Worked example and common mistakes
view.setFitWidth(240);
view.setPreserveRatio(true);

The view fits within the booking form without stretching the diagram. We set only fitWidth; JavaFX derives height from the original ratio. Display scaling does not resize or overwrite the PNG file.

Common mistakes: Do not confuse displayed dimensions with the image file’s dimensions.

Another context and its result

badge.setPreserveRatio(true);

Outcome: For a 480 × 240 image, the displayed sizes are 240 × 120 and 120 × 60 respectively.

What stays the same: Set fitWidth and preserveRatio on the view, not on the source image.

Prediction answer

It displays at 300 × 150. The original data remains 480 × 240.

Mouse clicks and persistent state

A mouse handler can update a field that remembers which image is selected. setOnMouseClicked registers an EventHandler<MouseEvent>; JavaFX passes a mouse event to handle. Our anonymous handler updates the field and then the ImageView. The initialized, nonempty image array is a prerequisite for modulo cycling. Changing the view leaves the booking input and result untouched. This is browsing venues, not confirming a reservation.

Key rule: Store the image index in a field and wrap it after the last image.

Worked example and common mistakes
index = (index + 1) % images.length;
view.setImage(images[index]);

Source corrections and boundaries

The PDF says a handler cannot access local variables in start. More precisely, an anonymous class may capture local variables that are final or effectively final. Reassigning the local reference breaks that condition; modifying the referenced control does not. Our examples use fields to keep shared state explicit. No lambda syntax is required.

The source’s wage example checks the numeric range but does not catch malformed text. Problem 2 deliberately adds NumberFormatException recovery. A nonnegative wage can include zero; the source message saying positive is narrower than its condition. Our booking rule is explicitly 1–4 inclusive.

The venue preview uses local, supplied images and assumes successful loading. A blank preview is a resource-path issue, not a seat-input error. Mouse clicking is the required 10.7 behavior; a keyboard-operable Next button is optional accessibility practice. Collections, bindings, FXML, background tasks, and deployment are deferred.

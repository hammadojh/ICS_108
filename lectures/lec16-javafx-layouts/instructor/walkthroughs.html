Problem 1: Display a booking summary

Create a window titled Campus booking that displays 3 seats: 30 SAR. The user must not be able to edit the displayed summary.

Expected window text:
3 seats: 30 SAR

What new concepts does it have?

Students will learn Launch a JavaFX application and display a non-editable text field in a window.

  • P1-C1 · Application lifecycle
  • P1-C2 · Stage
  • P1-C3 · Scene
  • P1-C4 · Pane and children
  • P1-C5 · TextField

Complete code

Run this snapshot as CampusBooking.java with Liberica Full JDK 25. Setup and file placement.

CampusBooking.javaComplete
import javafx.application.Application;
import javafx.stage.Stage;
import javafx.scene.Scene;
import javafx.scene.control.TextField;
import javafx.scene.layout.Pane;

// P1-C1: JavaFX calls start after launch.
public class CampusBooking extends Application {
  @Override
  public void start(Stage stage) {
    // P1-C5: Display a non-editable line.
    TextField summary = new TextField("3 seats: 30 SAR");
    summary.setEditable(false);
    summary.setPrefColumnCount(18);
    // P1-C4: Attach the field to its container.
    Pane pane = new Pane();
    pane.getChildren().add(summary);
    // P1-C3: A scene holds the pane.
    stage.setScene(new Scene(pane));
    // P1-C2: Title and show the window.
    stage.setTitle("Campus booking");
    stage.show();
  }
  public static void main(String[] args) {
    launch(args);
  }
}

Elaborated concepts for instructor reference

P1-C1 Application lifecycle

Call launch once; JavaFX calls your overridden start method.

The familiar main method starts the JavaFX runtime. The runtime creates the Application object and invokes start on the JavaFX Application Thread. Build the interface in start. @Override lets the compiler check the method signature; it does not call the method. Closing the last window normally ends this small application.

Common mistakes: Do not call start yourself or instantiate Stage before the JavaFX runtime starts.

Common mistake: Do not call start yourself or instantiate Stage before the JavaFX runtime starts.

P1-C2 Stage

Assign the title and scene, then call show to display the window.

The Stage passed to start is the primary window. Its title belongs to the operating-system title bar, not to the form inside the window. In our code, setScene attaches the prepared content before show is called.

Common mistakes: Constructing controls or setting a title alone does not display a window.

Common mistake: Constructing controls or setting a title alone does not display a window.

P1-C3 Scene

Give the scene a root node, then attach the scene to a Stage.

The scene is the content container; its root is the top of a tree of visible nodes. Here the root is a Pane and the TextField is its child. Stage → Scene → Pane → TextField describes containment, not inheritance. Replacing a scene replaces the window content.

Common mistakes: Do not confuse the Stage window with its Scene content.

Common mistake: Do not confuse the Stage window with its Scene content.

P1-C4 Pane and children

Create a control, then add it to the displayed container.

A control that exists only in a variable is not automatically on screen. getChildren returns the pane’s child-node list; add attaches a node. One plain Pane with one field is enough for Problem 1. GridPane later replaces this layout container while keeping the content.

Common mistakes: Creating a control without adding it leaves it invisible.

Common mistake: Creating a control without adding it leaves it invisible.

P1-C5 TextField

Use setText for its content and setEditable(false) for output-only text.

The constructor used here supplies initial text. setPrefColumnCount suggests a width in average text columns, not an input-length limit. A TextField holds String text even when that text looks numeric. Do not mistake a non-editable result for numeric storage.

Common mistakes: setPrefColumnCount does not cap the number of characters.

Common mistake: setPrefColumnCount does not cap the number of characters.

Trace: main calls launch; JavaFX calls start; the field becomes a child of the pane; the scene is attached to the stage; show displays the window.

Practice and answer: Change the booking to 4 seats at 10 SAR. The summary should read 4 seats: 40 SAR. Removing show leaves no visible window.

Complete code

Run this snapshot as CampusBooking.java with Liberica Full JDK 25. Setup and file placement.

CampusBooking.javaComplete
import javafx.application.Application;
import javafx.stage.Stage;
import javafx.scene.Scene;
import javafx.scene.control.TextField;
import javafx.scene.control.Label;
import javafx.scene.layout.GridPane;

public class CampusBooking extends Application {
  @Override
  public void start(Stage stage) {
    int seats = 3;
    int total = seats * 10;
    TextField seatsField = new TextField();
    TextField totalField = new TextField();
    seatsField.setEditable(false);
    totalField.setEditable(false);
    // P2-C3: Convert values to display text.
    seatsField.setText(Integer.toString(seats));
    totalField.setText(Integer.toString(total));
    // P2-C1: Describe each displayed value.
    Label seatsLabel = new Label("Seats:");
    Label totalLabel = new Label("Total (SAR):");
    // P2-C2: Add controls by column, then row.
    GridPane grid = new GridPane();
    grid.add(seatsLabel, 0, 0);
    grid.add(seatsField, 1, 0);
    grid.add(totalLabel, 0, 1);
    grid.add(totalField, 1, 1);
    stage.setScene(new Scene(grid));
    stage.setTitle("Campus booking");
    stage.show();
  }
  public static void main(String[] args) {
    launch(args);
  }
}

Elaborated concepts for instructor reference

P2-C1 Label

Use labels to explain what each value means.

Labels help students distinguish the meaning of two fields. Our labels say Seats: and Total (SAR):. A label can change through setText, but it is not an input editor. Optional accessibility depth: setLabelFor can associate a label with its input.

Common mistakes: Do not put user input in a Label and expect typing to modify it.

Common mistake: Do not put user input in a Label and expect typing to modify it.

P2-C2 GridPane coordinates

The order is node, column, row; the top-left cell is (0, 0).

Columns increase to the right; rows increase downward. Cells grow to fit their contents, so indices are not pixel coordinates. In Problem 2 we replace the Pane with GridPane, retaining the same three-seat booking and total. Each control is added once.

Common mistakes: Reversing row and column places controls in the wrong cell.

Common mistake: Reversing row and column places controls in the wrong cell.

P2-C3 Number-to-text conversion

Calculate with numbers, then convert the result for the field.

The multiplication still uses integer arithmetic. Only the result becomes display text. String concatenation is another familiar conversion route, but numeric addition and text concatenation are different operations. Changing the display text does not change the original numeric variable.

Common mistakes: Do not pass an int directly to setText.

Common mistake: Do not pass an int directly to setText.

Trace: Compute 3 × 10; convert 3 and 30 to text; add each label in column 0 and each field in column 1; display the grid in the scene.

Practice and answer: Change seats to 4: the fields show 4 and 40. Move the total field to (0, 1): it shares the label’s cell and may overlap it; restore (1, 1).

  • P3-C1 · Outer padding

Complete code

Run this snapshot as CampusBooking.java with Liberica Full JDK 25. Setup and file placement.

CampusBooking.javaComplete
import javafx.application.Application;
import javafx.stage.Stage;
import javafx.scene.Scene;
import javafx.scene.control.TextField;
import javafx.scene.control.Label;
import javafx.scene.layout.GridPane;
import javafx.geometry.Insets;

public class CampusBooking extends Application {
  @Override
  public void start(Stage stage) {
    int seats = 3;
    int price = 10;
    TextField seatsField = new TextField(Integer.toString(seats));
    TextField totalField = new TextField(Integer.toString(seats * price));
    TextField priceField = new TextField(Integer.toString(price));
    seatsField.setEditable(false);
    totalField.setEditable(false);
    priceField.setEditable(false);
    GridPane grid = new GridPane();
    grid.add(new Label("Seats:"), 0, 0);
    grid.add(seatsField, 1, 0);
    grid.add(new Label("Total (SAR):"), 0, 1);
    grid.add(totalField, 1, 1);
    grid.add(new Label("Price per seat (SAR):"), 0, 2);
    grid.add(priceField, 1, 2);
    // P3-C1: Keep content away from the edges.
    grid.setPadding(new Insets(16));
    // P3-C2: Separate columns and rows.
    grid.setHgap(12);
    grid.setVgap(8);
    stage.setScene(new Scene(grid));
    stage.setTitle("Campus booking");
    stage.show();
  }
  public static void main(String[] args) {
    launch(args);
  }
}

Elaborated concepts for instructor reference

P3-C1 Outer padding

Apply Insets to the grid to keep content away from its edges.

The single-number constructor uses the same value on all four sides. The four-number constructor follows top, right, bottom, left. Padding belongs to the layout region, so controls stay inset when its size changes. It does not alter the booking calculation.

Common mistakes: Do not confuse outer padding with the gaps between cells.

Common mistake: Do not confuse outer padding with the gaps between cells.

P3-C2 Grid gaps

Hgap separates columns; Vgap separates rows.

Problem 3 retains the two existing rows and adds a visible price row. The total is still three seats at ten SAR each. Grid spacing makes the form easier to scan; it neither changes coordinates nor creates extra empty rows.

Common mistakes: Do not add blank Labels just to simulate normal row spacing.

Common mistake: Do not add blank Labels just to simulate normal row spacing.

Trace: Retain seats and total; add the price row; apply outer padding and internal gaps; show the same booking with a more readable layout.

Practice and answer: Set price to 12: the price field shows 12 and the total 36. Double Vgap: only the spacing changes.

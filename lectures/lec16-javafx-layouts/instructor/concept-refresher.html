JavaFX windows and layouts

Build a visible booking form from ordinary Java objects. A JavaFX Application starts the interface, a Stage supplies its window, and a Scene displays a root layout container. Controls become visible when attached to that container. A GridPane then organizes the same booking into labeled rows with consistent spacing.

Mental model: Application starts → Stage hosts a Scene → the Scene has a root Pane → the pane contains controls. Values are calculated as numbers and displayed as text.

P1-C1 · 10.1 · pp. 1–3

Application lifecycle

Application supplies the lifecycle of a JavaFX program. The familiar main method starts the JavaFX runtime. The runtime creates the Application object and invokes start on the JavaFX Application Thread. Build the interface in start. @Override lets the compiler check the method signature; it does not call the method. Closing the last window normally ends this small application.

Key rule: Call launch once; JavaFX calls your overridden start method.

Worked example and common mistakes
public class CampusBooking extends Application {
  @Override
  public void start(Stage stage) { /* GUI setup */ }
}

The familiar main method starts the JavaFX runtime. The runtime creates the Application object and invokes start on the JavaFX Application Thread. Build the interface in start. @Override lets the compiler check the method signature; it does not call the method. Closing the last window normally ends this small application.

Common mistakes: Do not call start yourself or instantiate Stage before the JavaFX runtime starts.

Another context and its result
public class Attendance extends Application {
  @Override
  public void start(Stage stage) { /* GUI setup */ }
}

Outcome: Both classes receive their primary Stage when JavaFX invokes start. The comments stand for the window setup shown in the complete program.

What stays the same: Call launch once; JavaFX calls your overridden start method.

Predict: Does calling launch(args) repeatedly create one new application per call?

Prediction answer

No. Application.launch may be called only once in a running JVM. Close the program and run it again for a new launch.

P1-C2 · 10.1 · pp. 2–3

Stage

A Stage is a top-level window. The Stage passed to start is the primary window. Its title belongs to the operating-system title bar, not to the form inside the window. In our code, setScene attaches the prepared content before show is called.

Key rule: Assign the title and scene, then call show to display the window.

Worked example and common mistakes
stage.setTitle("Campus booking");
stage.show();

The Stage passed to start is the primary window. Its title belongs to the operating-system title bar, not to the form inside the window. In our code, setScene attaches the prepared content before show is called.

Common mistakes: Constructing controls or setting a title alone does not display a window.

Another context and its result
stage.setTitle("Attendance");
stage.show();

Outcome: The already-configured Stage becomes visible with the given title.

What stays the same: Assign the title and scene, then call show to display the window.

Predict: If show is removed, does setTitle display the window?

Prediction answer

No. Setting properties does not make the window visible; show does.

P1-C3 · 10.1 · pp. 1–3

Scene

A Scene holds the content displayed inside a Stage. The scene is the content container; its root is the top of a tree of visible nodes. Here the root is a Pane and the TextField is its child. Stage → Scene → Pane → TextField describes containment, not inheritance. Replacing a scene replaces the window content.

Key rule: Give the scene a root node, then attach the scene to a Stage.

Worked example and common mistakes
Scene scene = new Scene(pane);
stage.setScene(scene);

The scene is the content container; its root is the top of a tree of visible nodes. Here the root is a Pane and the TextField is its child. Stage → Scene → Pane → TextField describes containment, not inheritance. Replacing a scene replaces the window content.

Common mistakes: Do not confuse the Stage window with its Scene content.

Another context and its result
Scene scene = new Scene(attendancePane);
stage.setScene(scene);

Outcome: In each fragment the named pane must already exist. Its child controls become the scene content.

What stays the same: Give the scene a root node, then attach the scene to a Stage.

Predict: Can one Stage display two different scenes at the same time?

Prediction answer

No. A Stage has one scene at a time; separate stages can display different scenes.

P1-C4 · 10.1 · pp. 2–3

Pane and children

A Pane is a container whose children are graphical nodes. A control that exists only in a variable is not automatically on screen. getChildren returns the pane’s child-node list; add attaches a node. One plain Pane with one field is enough for Problem 1. GridPane later replaces this layout container while keeping the content.

Key rule: Create a control, then add it to the displayed container.

Worked example and common mistakes
Pane pane = new Pane();
pane.getChildren().add(summary);

A control that exists only in a variable is not automatically on screen. getChildren returns the pane’s child-node list; add attaches a node. One plain Pane with one field is enough for Problem 1. GridPane later replaces this layout container while keeping the content.

Common mistakes: Creating a control without adding it leaves it invisible.

Another context and its result
Pane pane = new Pane();
pane.getChildren().add(attendanceField);

Outcome: The previously created field joins the pane. A plain Pane does not arrange several fields into rows.

What stays the same: Create a control, then add it to the displayed container.

Predict: If a second field is added to a plain Pane without positioning it, does it appear on the next row?

Prediction answer

No. A plain Pane does not provide row layout; controls can overlap at the default position. Use GridPane for rows and columns.

P1-C5 · 10.1 · pp. 1–3

TextField

A TextField displays one line of text and can allow editing. The constructor used here supplies initial text. setPrefColumnCount suggests a width in average text columns, not an input-length limit. A TextField holds String text even when that text looks numeric. Do not mistake a non-editable result for numeric storage.

Key rule: Use setText for its content and setEditable(false) for output-only text.

Worked example and common mistakes
TextField summary = new TextField("3 seats: 30 SAR");
summary.setEditable(false);

The constructor used here supplies initial text. setPrefColumnCount suggests a width in average text columns, not an input-length limit. A TextField holds String text even when that text looks numeric. Do not mistake a non-editable result for numeric storage.

Common mistakes: setPrefColumnCount does not cap the number of characters.

Another context and its result
TextField status = new TextField("Present: 18");
status.setEditable(false);

Outcome: Both fields display text that the user cannot edit; code can still change it with setText.

What stays the same: Use setText for its content and setEditable(false) for output-only text.

Predict: Can status.setText("Present: 19") update the non-editable field?

Prediction answer

Yes. setEditable(false) prevents user editing; it does not prevent program updates.

P2-C1 · 10.3 · pp. 6–8

Label

A Label displays descriptive, non-editable text beside a control. Labels help students distinguish the meaning of two fields. Our labels say Seats: and Total (SAR):. A label can change through setText, but it is not an input editor. Optional accessibility depth: setLabelFor can associate a label with its input.

Key rule: Use labels to explain what each value means.

Worked example and common mistakes
Label seatsLabel = new Label("Seats:");

Labels help students distinguish the meaning of two fields. Our labels say Seats: and Total (SAR):. A label can change through setText, but it is not an input editor. Optional accessibility depth: setLabelFor can associate a label with its input.

Common mistakes: Do not put user input in a Label and expect typing to modify it.

Another context and its result
Label roomLabel = new Label("Room:");
roomLabel.setText("Room number:");

Outcome: The first label reads Seats:. The second ends with Room number:.

What stays the same: Use labels to explain what each value means.

Predict: Can the user type a new room number into roomLabel?

Prediction answer

No. A Label describes content; use an editable TextField to collect text.

P2-C2 · 10.3 · pp. 8–11

GridPane coordinates

A GridPane places controls in cells addressed by column and row. Columns increase to the right; rows increase downward. Cells grow to fit their contents, so indices are not pixel coordinates. In Problem 2 we replace the Pane with GridPane, retaining the same three-seat booking and total. Each control is added once.

Key rule: The order is node, column, row; the top-left cell is (0, 0).

Worked example and common mistakes
grid.add(seatsLabel, 0, 0);
grid.add(seatsField, 1, 0);

Columns increase to the right; rows increase downward. Cells grow to fit their contents, so indices are not pixel coordinates. In Problem 2 we replace the Pane with GridPane, retaining the same three-seat booking and total. Each control is added once.

Common mistakes: Reversing row and column places controls in the wrong cell.

Another context and its result
grid.add(roomLabel, 0, 1);
grid.add(roomField, 1, 1);

Outcome: The first pair shares row 0. The second pair shares row 1. Labels are left of their fields.

What stays the same: The order is node, column, row; the top-left cell is (0, 0).

Predict: Where does grid.add(roomField, 0, 2) place the field?

Prediction answer

Column 0, row 2: the first column and third row. It is not column 2.

P2-C3 · 10.3 · p. 7

Number-to-text conversion

Integer.toString converts an int value into String text. The multiplication still uses integer arithmetic. Only the result becomes display text. String concatenation is another familiar conversion route, but numeric addition and text concatenation are different operations. Changing the display text does not change the original numeric variable.

Key rule: Calculate with numbers, then convert the result for the field.

Worked example and common mistakes
int total = 3 * 10;
totalField.setText(Integer.toString(total));

The multiplication still uses integer arithmetic. Only the result becomes display text. String concatenation is another familiar conversion route, but numeric addition and text concatenation are different operations. Changing the display text does not change the original numeric variable.

Common mistakes: Do not pass an int directly to setText.

Another context and its result
int remaining = 20 - 6;
statusField.setText(Integer.toString(remaining));

Outcome: The booking field displays 30; the other field displays 14.

What stays the same: Calculate with numbers, then convert the result for the field.

Predict: Would totalField.setText(30) compile?

Prediction answer

No. setText expects a String. Integer.toString(30) supplies "30".

P3-C1 · 10.3 · pp. 11–12; single-value constructor is a teaching addition

Outer padding

Insets describes space at the top, right, bottom, and left edges of a region. The single-number constructor uses the same value on all four sides. The four-number constructor follows top, right, bottom, left. Padding belongs to the layout region, so controls stay inset when its size changes. It does not alter the booking calculation.

Key rule: Apply Insets to the grid to keep content away from its edges.

Worked example and common mistakes
grid.setPadding(new Insets(16));

The single-number constructor uses the same value on all four sides. The four-number constructor follows top, right, bottom, left. Padding belongs to the layout region, so controls stay inset when its size changes. It does not alter the booking calculation.

Common mistakes: Do not confuse outer padding with the gaps between cells.

Another context and its result
grid.setPadding(new Insets(10, 20, 10, 20));

Outcome: The first grid has 16 pixels on every side. The second has 10 top/bottom and 20 right/left.

What stays the same: Apply Insets to the grid to keep content away from its edges.

Predict: Does new Insets(10, 20, 10, 20) create 20 pixels between columns?

Prediction answer

No. Insets sets outer padding. Use setHgap for space between columns.

P3-C2 · 10.3 · pp. 11–12

Grid gaps

Horizontal and vertical gaps separate adjacent GridPane columns and rows. Problem 3 retains the two existing rows and adds a visible price row. The total is still three seats at ten SAR each. Grid spacing makes the form easier to scan; it neither changes coordinates nor creates extra empty rows.

Key rule: Hgap separates columns; Vgap separates rows.

Worked example and common mistakes
grid.setHgap(12);
grid.setVgap(8);

Problem 3 retains the two existing rows and adds a visible price row. The total is still three seats at ten SAR each. Grid spacing makes the form easier to scan; it neither changes coordinates nor creates extra empty rows.

Common mistakes: Do not add blank Labels just to simulate normal row spacing.

Another context and its result
grid.setHgap(0);
grid.setVgap(16);

Outcome: The first layout separates both columns and rows. The second has no added column gap and 16 pixels between rows.

What stays the same: Hgap separates columns; Vgap separates rows.

Predict: If Vgap changes from 8 to 20, do the field values change?

Prediction answer

No. Only the spacing changes; the numeric state and displayed values remain the same.

Problem 1: reproduce, change, explain

main calls launch; JavaFX calls start; the field becomes a child of the pane; the scene is attached to the stage; show displays the window.

Change the booking to 4 seats at 10 SAR. The summary should read 4 seats: 40 SAR. Removing show leaves no visible window.

Problem 2: reproduce, change, explain

Compute 3 × 10; convert 3 and 30 to text; add each label in column 0 and each field in column 1; display the grid in the scene.

Change seats to 4: the fields show 4 and 40. Move the total field to (0, 1): it shares the label’s cell and may overlap it; restore (1, 1).

Problem 3: reproduce, change, explain

Retain seats and total; add the price row; apply outer padding and internal gaps; show the same booking with a more readable layout.

Set price to 12: the price field shows 12 and the total 36. Double Vgap: only the spacing changes.

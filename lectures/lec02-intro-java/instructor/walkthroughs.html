IDE Demo — Instructor Cue Sheet

ICS 108 · Variables, input, output, comments, and errors

Target time
8–10 minutes

Demo principle: type a small change, predict what will happen, run it, and connect the result to the lecture. Keep the Console visible.

1. Orient students to the IDE · 1 minute

Project / filesWhere source files are stored.
EditorWhere Java code is written.
Run controlCompiles and executes the program.
ConsoleShows input, output, and messages.

Ask: “Which area is for the programmer, and which area is for the running program?”

2. Build the salary program incrementally · 5 minutes

  1. Create Salary.java and declare a variable

    public class Salary {
  public static void main(String[] args) {
    int wage;
    wage = 20;
  }
}

    Say: “int is the type, wage is the variable name, and = 20 stores a value.”

    Ask before running: “Will this program display anything?” Answer: No—there is no output statement.

  2. Add output and run

    System.out.println("Salary is " + wage * 40 * 52);

    Expected output: Salary is 41600

    Point out: quoted text prints literally; wage without quotes uses the stored value.

  3. Replace the fixed value with keyboard input

    import java.util.Scanner;

Scanner scnr = new Scanner(System.in);
int wage;
wage = scnr.nextInt();
System.out.println("Salary is " + wage * 40 * 52);

    Trace aloud: “The user types 20 → nextInt() reads it → wage stores it → the calculation uses it.”

    Ask: “If I enter 25, what should the program print?” Answer: Salary is 52000.

  4. Add one useful comment and format the code

    // Estimate annual salary: 40 hours for 52 weeks.
System.out.println("Salary is " + wage * 40 * 52);

    Say: “The compiler ignores the comment and most code whitespace. People do not.” Use the IDE’s formatting shortcut if available.

Errors and Applied Demo

Make one mistake at a time, let students predict, then repair it.

Target time
6–8 minutes

3. Demonstrate errors and warnings · 3 minutes

Change to makeTypeWhat to show
Remove the semicolon after int wage.Syntax errorCompilation stops. Read the first compiler message, repair it, and compile again.
Change 52 weeks to 50.Logic errorThe program runs, but the answer is wrong. The compiler cannot know the intended number of weeks.
Add int zero = 0; and print 10 / zero.Runtime errorCompilation succeeds; execution fails with an ArithmeticException.
Hover over a yellow underline, if the IDE shows one.Warning / inspectionIt usually does not stop the program. Read it and investigate; exact IDE warnings vary.

Recovery habit: after every repair, run again. Fix the first reported error before chasing later messages.

4. Married-couple names mini-demo · 3–4 minutes

Explain the algorithm first: read four strings, then combine them into five output lines.

import java.util.Scanner;

public class MarriedNames {
  public static void main(String[] args) {
    Scanner scnr = new Scanner(System.in);

    String firstName1 = scnr.nextLine();
    String lastName1  = scnr.nextLine();
    String firstName2 = scnr.nextLine();
    String lastName2  = scnr.nextLine();

    System.out.println(firstName1 + " " + lastName1 + " and "
        + firstName2 + " " + lastName2);
    System.out.println(firstName1 + " and " + firstName2 + " " + lastName1);
    System.out.println(firstName1 + " and " + firstName2 + " " + lastName2);
    System.out.println(firstName1 + " and " + firstName2 + " "
        + lastName1 + "-" + lastName2);
    System.out.println(firstName1 + " and " + firstName2 + " "
        + lastName2 + "-" + lastName1);
  }
}

Enter

Pat
Smith
Kelly
Jones

Expected output

Pat Smith and Kelly Jones
Pat and Kelly Smith
Pat and Kelly Jones
Pat and Kelly Smith-Jones
Pat and Kelly Jones-Smith

Ask: “Where are the spaces and hyphens coming from?” Answer: They are string literals written inside quotes.

5. Final instructor checklist

  • Increase the editor and Console font size before class.
  • Keep the project prepared, but type the important lines live.
  • Run after every meaningful change.
  • Ask students to predict before clicking Run.
  • Keep input order visible when using nextLine().
  • If time is short, skip the runtime-error demonstration.

Control flow is state plus questions.

Lecture abstract

Branches and loops use Boolean conditions to control execution. A branch asks once at a decision point and selects a path. A loop asks again after every iteration and repeats while its condition remains true. Correctness therefore depends on four connected ideas: the condition must express the intended rule, the structure must match the relationship among actions, the state must change predictably, and repetition must have a reachable exit. Teach students to trace condition, path, state, and exit together.

01

§§3.1, 4.1 · Control flow

Branches select; loops select and return

Normal execution moves statement by statement. Both branches and loops interrupt that straight line with a Boolean question. A branch follows one path and then continues. A loop follows its true path back to the same question, creating possible repetition.

Key rule

if checks once each time execution reaches it. while checks before every possible iteration.

Expand the two execution shapes

Branch

if (condition) {
   body;
}
after;
  1. Evaluate the condition.
  2. Run or skip the body.
  3. Continue at after.

Loop

while (condition) {
   body;
   update;
}
after;
  1. Evaluate the condition.
  2. If true, complete the body and update.
  3. Return to the condition; false continues at after.

Once a loop iteration begins, Java completes the body before checking the condition again—even if some statement midway changes the controlling state.

Useful teaching line

“A branch rejoins the program. A loop returns to its question.”

02

§§3.1, 3.3–3.4 · Branch forms

Branch structure expresses the relationship among cases

if makes one action conditional. if-else selects exactly one of two alternatives. An else if chain is an ordered search: the first true condition wins and every remaining branch is skipped.

Key rule

Order is semantic. Put specific or high thresholds before broader ones, and use separate ifs only when several actions may independently occur.

Expand first-true reasoning
if (score >= 90) grade = "A";
else if (score >= 80) grade = "B";
else if (score >= 70) grade = "C";
else grade = "Below C";

For 83, the 90 test is false and the 80 test is true. Java stores B and skips the rest. The path reaching the B test already proves score < 90, so the test describes the remaining lower boundary only.

OrderResult for 95
90, 80, 70, 60A — intended
60, 70, 80, 90D or better — later grades hidden
Useful teaching line

“Every failed condition adds a fact to the path that continues.”

Expand one chain versus independent decisions

One category

if (score >= 90) grade = "A";
else if (score >= 80) grade = "B";

At most one category wins.

Several actions

if (hasID) allowEntry();
if (hasCoupon) applyDiscount();

Both actions may happen.

03

§§3.2, 3.4–3.5 · Comparisons and logic

Boolean expressions draw the boundaries

Relational and equality operators produce Booleans. Inclusive operators keep their boundary value; exclusive operators reject it. && requires both conditions, || accepts either, and ! reverses a Boolean.

Key rule

Translate the English rule first. “13 through 19” becomes age >= 13 && age <= 19.

Expand range translation and tests
PhraseConditionEvidence
at least 13age >= 1312 F, 13 T
less than 20age < 2019 T, 20 F
13 through 19age >= 13 && age <= 1912 F, 13 T, 19 T, 20 F

Java cannot read 13 <= age <= 19; each comparison must be complete. One equals assigns; two equals compare. For an int, if (age = 19) fails to compile because the condition is not Boolean.

Expand AND, OR, NOT, and grouping
boolean morning = hour >= 8 && hour < 12;
boolean afternoon = hour >= 13 && hour < 17;
boolean officeOpen = morning || afternoon;

if (!officeOpen) {
   System.out.println("Closed");
}

AND narrows within each interval; OR broadens across alternative intervals. Name complex decisions and parenthesize logical groups when the visual grouping helps the reader.

§§4.1–4.2 · While loops

A pre-check loop may execute zero or many times

A while loop evaluates its condition before entering the body and again after every completed iteration. Each body execution is one iteration. The final false condition check is part of the execution trace even though it does not create an iteration.

Key rule

Trace state at every condition check: true enters the complete body; false exits immediately.

Expand a complete while-loop trace
int count = 0;
while (count < 3) {
   System.out.print(count + " ");
   count++;
}
State at checkConditionAction
count = 0trueprint 0; update to 1
count = 1trueprint 1; update to 2
count = 2trueprint 2; update to 3
count = 3falseexit

Output is 0 1 2. The false check at 3 proves why no fourth iteration occurs. If count began at 3, the body would execute zero times.

Useful teaching line

“Trace checks and iterations separately: a check can occur without a body execution.”

05

§4.2 · Loop progress

Termination is a claim about changing state

A loop stops only when a later condition becomes false. Correct termination therefore requires a controlling state, a progress step that changes it in the needed direction, and a reachable boundary that makes the condition false.

Key rule

For every loop, identify the state, direction, boundary, and reason that repeated updates must reach the exit.

Expand a small termination proof
int count = 0;
while (count < 3) {
   System.out.println(count);
   count++;
}
  1. State: count controls the condition.
  2. Direction: every iteration increases it by exactly 1.
  3. Boundary: the condition becomes false when count reaches 3.
  4. Conclusion: starting at 0, three updates produce 3, so the next check exits.

Remove count++ and the body repeats forever because the condition keeps seeing 0 < 3. A wrong-direction update such as count-- also moves away from the exit.

Expand safe recovery from an infinite loop

Stop the running program in the IDE. Do not start editing while it is still producing output. Reconstruct the controlling state and ask whether the body changes it. Restore a known intended update, rebuild, and rerun the same small input that exposed the issue.

Useful teaching line

“A condition describes the exit; progress makes the exit reachable.”

06

§4.3 · Sentinel loops, counters, accumulators

Unknown input counts need an explicit stopping signal

A sentinel is a special input value that ends repetition. It controls the loop but is not part of the data. Accumulators combine processed values; counters record how many values were processed.

Key rule

Use the pattern read → test → process → read again. The repeated read is the progress step.

Expand the sentinel pattern and trace
int total = 0;
int count = 0;
int value = input.nextInt();

while (value != 0) {
   total += value;
   count++;
   value = input.nextInt();
}

For 5 7 2 0, the body processes 5, 7, and 2. It exits when the next check sees 0, producing total 14 and count 3. The sentinel is not added and not counted. If the first value is 0, the body does not run.

Before computing an average, branch on count > 0; a valid run can contain zero data values.

07

§4.4 · For loops

A for loop exposes a known counting rule

A for loop places initialization, continuation condition, and update together. It is the natural default when the number of iterations or the index range is known before the loop starts.

Key rule

Execution order is initialize once → test → body → update → test again. Use while when repetition is controlled by an event or sentinel instead of a known count.

Expand execution order and off-by-one reasoning
for (int i = 0; i < 5; i++) {
   System.out.print(i + " ");
}

The body receives 0, 1, 2, 3, and 4: five iterations. The update then produces 5, and 5 < 5 is false. The first exit value does not enter the body.

Intended valuesConditionCount
indices 0 through 4i < 55
human counts 1 through 5i <= 55

Diagnose off-by-one errors by naming the start, first body value, last body value, and first exit value before changing the operator.

Expand the while-versus-for choice

Prefer for

Process exactly 10 scores; visit every character; repeat once per row.

Prefer while

Read until 0; retry while invalid; continue until an external state changes.

The forms are mechanically interchangeable in many cases. The teaching goal is readable intent, not proving that only one syntax can work.

08

§§3.5, 4.4, 4.6 · Composed control flow

Loops provide coverage; branches classify each item

Useful programs often repeat one local decision. The outer loop determines which item is current. A branch inside the body decides how that item affects counters, accumulators, output, or other state.

Key rule

Read nesting from outside in: “for every item, make this decision.” Track the current item separately from the state that persists across iterations.

Expand a score-report composition
int total = 0;
int passed = 0;

for (int i = 0; i < scoreCount; i++) {
   int score = input.nextInt();
   total += score;
   if (score >= 60) {
      passed++;
   }
}

double average = total / (double) scoreCount;

The loop guarantees that every score is processed. The branch classifies the current score. total and passed persist because they are declared outside the body. The average is computed after the set is complete.

A useful invariant is: after each iteration, passed equals the number of passing scores among the scores processed so far.

Expand string iteration with a branch
for (int i = 0; i < word.length(); i++) {
   char letter = word.charAt(i);
   if (letter == 'a' || letter == 'e') {
      vowelCount++;
   }
}

A string of length N has valid indices 0 through N - 1. Therefore the condition is i < word.length(). Using <= attempts charAt(length) and fails at runtime.

09

§§4.7, 4.10 · Nested loops and scope

Nesting multiplies work; scope limits names

A nested loop runs its inner loop fully for every outer iteration. Variables declared in a block are visible only within that block. Together, these rules determine both how often code runs and which state survives afterward.

Key rule

Trace the inner variable fastest. Declare a value outside the loop only when its result must persist after an iteration or after the loop.

Expand the nested-loop trace
for (int row = 1; row <= 2; row++) {
   for (int col = 1; col <= 3; col++) {
      System.out.print(row + "," + col + " ");
   }
}

The pairs are 1,1; 1,2; 1,3; 2,1; 2,2; 2,3. Two outer iterations times three inner iterations produce six executions of the inner body. The inner counter restarts for every outer iteration because its initialization runs each time execution reaches the inner for.

Expand loop-variable scope
int total = 0;

for (int i = 0; i < 3; i++) {
   int score = input.nextInt();
   total += score;
}

System.out.println(total);
// i and score are not visible here

total survives because it is declared outside. The index i is scoped to the loop. score is block-local and is recreated during each iteration. Small scope reduces accidental reuse; wider scope is justified only by a wider need.

§§3.8, 4.2, 4.4 · Testing and recovery

Debug with predicted paths and state transitions

Control-flow bugs often compile. Evidence comes from boundary inputs, small traces, and invariants. For branches, find the first unexpected condition result. For loops, find the first check or update where observed state differs from the prediction.

Key rule

State the rule → choose boundary or small-count inputs → predict every check → run → compare at the first mismatch.

Expand compile-time, runtime, and logic-error recovery
Error kindExampleRecovery evidence
Compile timeif (age = 19) does not produce Boolean.Restore the intended comparison; rebuild.
RuntimecharAt(length) is outside valid string indices.Restore i < length; rerun the same word.
LogicA broad branch wins early or i <= n runs once too often.Trace boundary cases and the first exit value.
Non-terminationA while body never updates controlling state.Stop execution, restore progress, rerun the same input.

Do not promise exact IDE wording. Teach a repeatable recovery loop: stop if needed, restore the last known intended line, rebuild, and rerun the same evidence-producing input.

Expand the minimum test suite
  • Branch threshold: just below and at the boundary, such as 59/60 or 79/80.
  • Counting loop: N = 0, N = 1, and one ordinary value.
  • Sentinel loop: sentinel first, one data value then sentinel, several values then sentinel.
  • String loop: empty if allowed, one character, and a word where the last character matters.
  • Integrated report: all pass, all fail, and values on both sides of 60.
Useful teaching line

“A boundary is where the behavior changes; that is where our evidence must be strongest.”
